{\Large \textbf{NanoPitch Project Reflection}} \hfill \textbf{Priontu Chowdhury}

\vspace{0.4em}
\textbf{Overview}
\begin{itemize}
    \item My goal was to improve mean RPA while preserving real-time performance. I started from the default baseline model (\texttt{cond\_size=64}, \texttt{gru\_size=96}, default training, no noise addition, no SpecAugment), then tested structured changes including SpecAugment, model-size sweeps, f0-consistent voicing, cosine annealing, time masking, early stopping, SNR curriculum, checkpoint fine-tuning, and finally resume-from-baseline augmentation.
\end{itemize}

\textbf{Modifications}
\begin{itemize}
    \item Ran a sweep over \texttt{cond\_size}, \texttt{gru\_size}, and frequency-mask width; the strongest sweep settings used \texttt{specaugment\_band=2} with (\texttt{cond\_size=64}, \texttt{gru\_size=96}), (\texttt{cond\_size=96}, \texttt{gru\_size=64}), and (\texttt{cond\_size=96}, \texttt{gru\_size=128}).
    \item Built a stronger test-side training pipeline with f0-consistent voiced targets, cosine annealing, time masking, early stopping, and an SNR curriculum.
    \item Created a conservative fine-tuning experiment from the default checkpoint and then a resume-with-augmentation experiment using the same baseline architecture.
\end{itemize}

\textbf{Rationale}
\begin{itemize}
    \item Early results suggested that training from scratch with heavier augmentation often hurt raw RPA, so I shifted strategy from ``more augmentation from scratch'' to ``start from the strongest clean model and add robustness carefully.''
    \item I also found a mismatch between VAD labels and \texttt{f0>0}, so I tested f0-consistent voiced supervision to better align training and evaluation.
\end{itemize}

\textbf{Impact on Performance}
\begin{itemize}
    \item The default baseline model (\texttt{cond\_size=64}, \texttt{gru\_size=96}, default training, no noise addition, no SpecAugment) remained very strong for a long time: average offline RPA \(=0.9209\), realtime RPA \(=0.9028\), VAD accuracy \(=0.8693\), offline median cents \(=32.20\), and realtime median cents \(=40.80\).
    \item The best overall model resumed that same default checkpoint and then applied the full augmented recipe (\texttt{cond\_size=64}, \texttt{gru\_size=96}, \texttt{epochs=100}, \texttt{batch\_size=384}, \texttt{lr=1.5e-3}, \texttt{min\_lr=2e-5}, \texttt{seq\_len=200}, \texttt{w\_pitch=1.5}, \texttt{w\_vad=0.1}, \texttt{snr\_range=[-5,20]}, \texttt{specaugment\_band=2}, \texttt{time\_mask=12}, cosine annealing, early stopping, and a 20-epoch SNR curriculum).
    \item Compared with the default, this augmented resumed model improved offline RPA to \(0.9299\) (\(+0.0089\)), realtime RPA to \(0.9054\) (\(+0.0026\)), VAD accuracy to \(0.9274\) (\(+0.0581\)), reduced offline median cents to \(21.81\) (\(-10.39\)), and reduced realtime median cents to \(31.14\) (\(-9.66\)).
\end{itemize}

\textbf{Comparison}
\begin{itemize}
    \item What worked: moderate SpecAugment (\texttt{band=2}), larger conditioning sizes (\texttt{64} or \texttt{96}), and most importantly resuming from the strong default checkpoint before adding augmentation.
    \item What did not work as well: training the full augmentation stack from scratch. Those models were systematic and reproducible, but they did not beat the raw RPA of the default baseline.
    \item Main takeaway: the best strategy was not replacing the baseline, but preserving its strong optimization basin and then fine-tuning it with targeted augmentation.
\end{itemize}
